# Standar Dokumen & Presentasi (PPT, Proposal)

Standar wajib untuk setiap deck PPT dan proposal Word yang dibuat untuk Sujarwadi / L&D BBM.
Acuan kualitas: deck konsultan global kelas atas. Bukan presentasi kelas, bukan laporan teknis.

## 1. Judul slide
- **Headline pendek dan tegas: 2–6 kata, Title Case, tanpa titik.** Contoh benar: `Akar Masalah`, `Satu Jalur, Lima Peran`, `Sales Junior: Mesin Konversi`, `Kerangka Pengukuran`.
- **Dilarang** judul berbentuk kalimat bercerita atau "orang ngomong": tidak memakai rangkaian `yang`, `bahwa`, `sehingga`, `bukan ... melainkan`, tidak memakai titik koma, tidak lebih dari satu baris.
- Pola `Subjek: Penegasan` boleh (mis. `Sales Senior: Pemilik Akun`), selama tetap ringkas.
- Pesan/argumen dibawa oleh isi slide (data, diagram, callout), bukan oleh judul yang panjang.
- Label bagian kecil (huruf kapital, merah) di atas judul untuk navigasi, mis. `SALES DEVELOPMENT PROGRAM · 2/4`.

## 2. Alur cerita
- Struktur: Cover → Ringkasan Eksekutif → Situasi (data) → Akar Masalah → Solusi/Arsitektur → Detail per komponen → Kesinambungan → Pengukuran → Roadmap → Keputusan yang Diperlukan.
- Satu pesan per slide. Setiap komponen program mendapat **satu halaman utuh** yang menjawab: mengapa krusial (urgensi berbasis data), pergeseran peran (dari → ke), penentu sukses, perjalanan belajar, komponen 70/20, gerbang, KPI, jam.
- Pembeda antar level/komponen harus terlihat eksplisit (matriks pembeda, risiko bila tidak dikembangkan).

## 3. Visual
- Kanvas 16:9 lebar. Palet: navy `0B1F33` dominan, merah `B3121E` sebagai aksen tunggal, biru `2F5D8A`, abu muda `F2F4F7`. Font Arial.
- Setiap slide punya elemen visual (grafik native, diagram, tangga, chevron, heatmap, Gantt, kartu). Tidak ada slide teks polos.
- Cover tidak boleh polos: panel warna + motif visual program (mis. tangga karier).
- Tidak ada garis aksen di bawah judul, tidak ada strip dekoratif di tepi.
- Sumber data di kaki slide (9 pt), nomor halaman, label kerahasiaan.
- Render dan periksa setiap slide sebelum dikirim: tidak ada teks terpotong, bertumpuk, atau kotak kosong besar.

## 4. Isi
- Angka internal harus bersumber (master data, rekam training, TNA). Klaim tanpa data ditandai sebagai asumsi/usulan.
- **Jangan menyebut nama perusahaan pembanding/kompetitor (benchmark) di dokumen yang dibagikan.** Benchmark hanya untuk diskusi internal dengan Sujarwadi.
- Hal yang masih perlu persetujuan ditulis sebagai "usulan".

## 5. Proposal Word
- Sampul, daftar isi, ringkasan eksekutif 1 halaman, bab bernomor, tabel berheader navy, lampiran, daftar pustaka.
- Heading bab juga ringkas (mis. `6. Kacab Academy`), bukan kalimat.

## 6. File
- Setiap revisi diberi akhiran versi (`_v2`, `_v3`) supaya tidak tertukar dengan versi lama.
